# 멀티모달 우울증 판별 서비스 - 핵심 기술 정리

> 이 문서는 프로젝트의 **차별화된 핵심 기술**과 **왜 이 기술을 선택했는가**를 정리합니다.

---

## 1. 이미지 모델: ConvNeXt-Base 기반 얼굴 표정 분류

### 선택 이유

| 기존 방식의 한계 | 해결 필요성 |
|-----------------|------------|
| **ResNet50**은 2015년 아키텍처로 최신 Vision Transformer 대비 성능 열위 | 더 높은 특성 추출 능력이 필요 |
| **ViT (Vision Transformer)**는 대규모 데이터셋 필요, 소규모 데이터에서 과적합 위험 | 제한된 얼굴 데이터셋에서도 안정적 학습 필요 |
| **EfficientNet**은 복합 스케일링으로 복잡도가 높아 하이퍼파라미터 튜닝 어려움 | 직관적인 구조로 빠른 실험 필요 |

#### 대안 비교 및 선택 근거

| 모델 | 장점 | 단점 | 선택 여부 |
|------|------|------|----------|
| **ResNet50** | 널리 검증됨, Transfer Learning 용이 | 2015년 아키텍처, 성능 한계 | 초기 실험용 |
| **ViT-B/16** | SOTA 성능, 전역 컨텍스트 학습 | 대규모 데이터 필요, 학습 불안정 | X |
| **EfficientNet-B0** | 효율적 파라미터 사용 | 복합 스케일링 튜닝 복잡 | X |
| **ConvNeXt-Base** | CNN의 안정성 + Transformer 수준 성능 | 비교적 최신 (2022) | **O (최종 선택)** |

**ConvNeXt 선택 이유**:
1. **CNN 기반 안정성**: ViT와 달리 소규모 데이터셋에서도 안정적으로 학습
2. **Transformer 수준 성능**: Swin Transformer와 동등한 성능을 CNN 구조로 달성
3. **Transfer Learning 친화적**: ImageNet 사전학습 가중치가 얼굴 특성 추출에 효과적
4. **단순한 구조**: 하이퍼파라미터 튜닝이 직관적

### 구현 방법

- **구현 파일**: 
  - `hwa_in/combind/image/image_model.py` (모델 정의)
  - `hwa_in/clean_training.ipynb` (학습 파이프라인)

- **핵심 로직**:
  ```python
  # ConvNeXt-Base 백본 + 커스텀 분류기
  class DepressionClassifier(nn.Module):
      def __init__(self, dropout_rate=0.5):
          super().__init__()
          # ImageNet 사전학습 가중치 로드
          weights = ConvNeXt_Base_Weights.IMAGENET1K_V1
          self.backbone = convnext_base(weights=weights)
          
          # 원래 분류기 제거 후 우울/비우울 이진 분류기로 교체
          in_features = self.backbone.classifier[-1].in_features
          self.backbone.classifier[-1] = nn.Identity()
          self.classifier = nn.Sequential(
              nn.Dropout(p=dropout_rate),
              nn.Linear(in_features, 2)  # 2-class: 우울/비우울
          )
  ```

- **참고 문서**: 
  - [ConvNeXt 논문 (CVPR 2022)](https://arxiv.org/abs/2201.03545)
  - [PyTorch ConvNeXt](https://pytorch.org/vision/stable/models/convnext.html)

### 핵심 기능

1. **3-Phase Training 전략**: 1 에포크 테스트 → 하이퍼파라미터 조정 → Early Stopping 본학습
2. **Backbone Freezing**: 초기 5 에포크 동안 백본 고정 → 이후 전체 Fine-tuning
3. **감정 → 우울 매핑**: 7가지 감정(anxiety, hurt, sadness 등)을 우울/비우울 이진 라벨로 변환

## 2. 사운드 모델: 프로소디(Prosody) 기반 감정 분석

### 선택 이유

| 기존 방식의 한계 | 해결 필요성 |
|-----------------|------------|
| **Wav2Vec2, HuBERT** 등 음성 모델은 "무엇을 말했는가"에 집중 | 우울증은 "어떻게 말했는가"(억양, 강세, 리듬)가 더 중요한 지표 |
| **MFCC 단독 사용**은 음소(Phoneme) 정보가 과도하게 포함됨 | 언어/내용에 독립적인 운율 특성 추출 필요 |
| **1D 오디오 모델**은 시각적 패턴 인식 불가 | 멜 스펙트로그램의 2D 패턴을 활용하면 CNN 전이학습 가능 |

#### 대안 비교 및 선택 근거

| 접근법 | 장점 | 단점 | 선택 여부 |
|--------|------|------|----------|
| **Wav2Vec2 Fine-tuning** | SOTA 음성 인식 | 내용(Content) 중심, 프로소디 약함 | X |
| **MFCC + LSTM** | 시계열 학습 | 음소 정보 과다, 언어 의존적 | X |
| **OpenSMILE 특성** | 풍부한 음향 특성 | 수백 개 특성, 해석 어려움 | X |
| **Prosody 3채널 + CNN** | 운율 특화, ImageNet 전이학습 가능 | 커스텀 전처리 필요 | **O (최종 선택)** |

**프로소디 3채널 방식 선택 이유**:
1. **음소 내용 희석**: Avg Pooling으로 "무슨 말을 했는지"를 흐리게 만듦
2. **운율만 추출**: 억양(Pitch), 강세(Energy), 리듬(Mel 패턴)만 남김
3. **ImageNet 전이학습**: 멜 스펙트로그램을 "이미지"처럼 처리 → ConvNeXt 활용 가능
4. **언어 독립성**: 한국어/영어 무관하게 운율 패턴 분석 가능

### 구현 방법

- **구현 파일**: `hwa_in/combind/sound/sound_model.py`

- **핵심 로직 (3채널 프로소디 텐서 생성)**:
  ```python
  def wav_to_prosody_tensor(path: str) -> torch.Tensor:
      # 1) 멜 스펙트로그램 (저해상도 + 블러링으로 음소 희석)
      Smel = mel_spec(y_t)
      Smel_low = _avg_pool_2d(Smel, k_freq=4, k_time=4)  # 핵심: 4x4 풀링으로 내용 희석
      ch_mel = _resize_to(Smel_low, original_size)
      
      # 2) 피치(F0) → 가우시안 띠 (억양 패턴)
      f0, _, _ = librosa.pyin(y, fmin=50, fmax=800)
      ch_pitch = _f0_to_band(f0, sigma=1.5)  # 피치를 2D 밴드로 변환
      
      # 3) RMS 에너지 (강세/리듬)
      rms = librosa.feature.rms(y=y)
      ch_rms = normalize(rms)
      
      # 4) 3채널 스택 → [3, 224, 224] 텐서
      x = torch.cat([ch_mel, ch_pitch, ch_rms], dim=0)
      return F.interpolate(x, size=(224, 224))
  ```

- **참고 문서**:
  - [librosa pYIN Pitch Detection](https://librosa.org/doc/main/generated/librosa.pyin.html)
  - [Prosody in Depression Detection (Survey)](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC7796247/)

### 핵심 기능

1. **3채널 프로소디 텐서**: Mel(음색) + Pitch(억양) + RMS(강세)를 RGB처럼 결합
2. **7-클래스 감정 분류 → 우울 점수 변환**: 슬픔(0.4), 중립(0.3) 등 가중치 적용
3. **음소 내용 희석**: 4x4 Average Pooling으로 "무슨 말인지"를 의도적으로 제거

#### 우울 점수 계산 공식

```python
# 긍정 감정
POS = (happiness + surprise) / 2

# 부정 감정 (슬픔에 가장 높은 가중치)
NEG_weighted = (0.4 * sadness + 0.3 * neutral + 0.1 * fear 
                + 0.1 * disgust + 0.1 * anger) / 5

# 최종 우울 점수 (0~1)
score = NEG_weighted / (NEG_weighted + POS + 1e-8)
```

**슬픔 가중치 0.4 설정 근거**: 우울증의 핵심 증상이 지속적 슬픔(Persistent Sadness)이므로 가장 높은 가중치 부여

## 3. 텍스트 모델: KoBERT 임베딩 + Logistic Regression

### 선택 이유

| 기존 방식의 한계 | 해결 필요성 |
|-----------------|------------|
| **BERT Fine-tuning**은 소규모 데이터에서 과적합 위험 | 안정적인 분류기 필요 |
| **TF-IDF + SVM**은 문맥 정보 손실 | 문맥을 고려한 임베딩 필요 |
| **GPT 계열**은 생성 모델로 분류 태스크에 과잉 | 단순 분류에는 임베딩만 충분 |

#### 대안 비교 및 선택 근거

| 접근법 | 장점 | 단점 | 선택 여부 |
|--------|------|------|----------|
| **KoBERT Fine-tuning** | End-to-end 학습 | 소규모 데이터 과적합, GPU 메모리 과다 | X |
| **KoGPT2 + Classification Head** | 생성+분류 가능 | 불필요한 복잡도 | X |
| **TF-IDF + Logistic Regression** | 빠름, 해석 가능 | 문맥 정보 없음 | X |
| **KoBERT Embedding + Logistic Reg** | 문맥 임베딩 + 단순 분류기 | 2단계 파이프라인 | **O (최종 선택)** |

**KoBERT + Logistic Regression 선택 이유**:
1. **풍부한 의미 정보**: KoBERT(768-dim)가 이미 충분한 문맥 정보 포함
2. **과적합 방지**: 단순한 Linear 레이어로 복잡도 최소화
3. **해석 가능성**: 각 차원의 가중치를 분석하여 어떤 특성이 중요한지 파악 가능
4. **빠른 추론**: 임베딩만 추출하면 분류는 O(1) 연산

### 구현 방법

- **구현 파일**: `hwa_in/combind/text/text_model.py`

- **핵심 로직**:
  ```python
  # 임베더: 한국어 특화 Sentence-BERT
  embedder = SentenceTransformer("jhgan/ko-sbert-multitask", device=device)
  
  # 분류기: 단순 Logistic Regression
  class LogisticRegression(nn.Module):
      def __init__(self, input_dim=768, num_classes=2):
          super().__init__()
          self.linear = nn.Linear(input_dim, num_classes)
      
      def forward(self, x):
          return self.linear(x)  # 768-dim → 2-class
  ```

- **참고 문서**:
  - [KoBERT (SKT)](https://github.com/SKTBrain/KoBERT)
  - [Sentence-Transformers](https://www.sbert.net/)

### 핵심 기능

1. **STT(Speech-to-Text)**: Google Speech API로 음성 → 텍스트 변환
2. **텍스트 정규화**: 괄호, 특수문자 제거 → 노이즈 최소화
3. **768-dim 임베딩**: KoBERT의 문맥 정보를 그대로 활용

## 4. 멀티모달 통합: AutoPredict 클래스

### 선택 이유

| 기존 방식의 한계 | 해결 필요성 |
|-----------------|------------|
| **Late Fusion (단순 평균)**은 모달리티별 중요도 미반영 | 가중치 기반 통합 필요 |
| **Early Fusion (특성 결합)**은 차원이 너무 커지고 모달리티 결측 처리 어려움 | 독립적 예측 후 통합 필요 |
| **Joint Training**은 학습 불안정, 디버깅 어려움 | 각 모델 독립 학습 후 통합 |

#### 대안 비교 및 선택 근거

| 통합 방식 | 장점 | 단점 | 선택 여부 |
|----------|------|------|----------|
| **Early Fusion** | End-to-end 학습 | 차원 폭발, 결측 처리 어려움 | X |
| **Joint Training** | 최적화된 통합 | 학습 불안정, 디버깅 어려움 | X |
| **Late Fusion (평균)** | 단순, 안정적 | 모달리티 중요도 미반영 | X |
| **Late Fusion (가중 평균)** | 모달리티별 가중치 조절 가능 | 가중치 튜닝 필요 | **O (최종 선택)** |

**Late Fusion + 가중 평균 선택 이유**:
1. **모달리티 독립성**: 각 모델을 개별 학습 → 디버깅/개선 용이
2. **결측 처리**: STT 실패 시 텍스트 결과만 제외하고 나머지 사용 가능
3. **가중치 조절**: 도메인 지식 기반으로 이미지(0.4) > 사운드(0.35) > 텍스트(0.25) 설정
4. **확장성**: 새로운 모달리티 추가 시 기존 모델 수정 불필요

### 구현 방법

- **구현 파일**: `hwa_in/combind/AutoPredict.py`

- **핵심 로직**:
  ```python
  class AutoPredict:
      def combind_predict(self, image_file, sound_file):
          """3개 모달리티를 독립 예측 후 결합"""
          image_result = self.image_predict(image_file)   # 얼굴 표정
          sound_result = self.sound_predict(sound_file)   # 운율/프로소디
          text_result = self.text_predict(sound_file)     # 발화 내용 (STT)
          
          return {
              "image": image_result,  # {"pred": 0/1, "conf": float}
              "sound": sound_result,
              "text": text_result
          }
  ```

- **권장 최종 진단 로직**:
  ```python
  # 가중 평균 방식 (권장)
  def get_weighted_prediction(results):
      weights = {'image': 0.4, 'sound': 0.35, 'text': 0.25}
      score = (weights['image'] * results['image']['conf'] +
               weights['sound'] * results['sound']['conf'] +
               weights['text'] * results['text']['conf'])
      return 1 if score > 0.5 else 0
  ```

### 핵심 기능

1. **독립적 예측**: 각 모달리티가 개별 모델로 예측 수행
2. **유연한 통합**: 다수결, 가중 평균 등 다양한 통합 전략 적용 가능
3. **결측 내성**: 하나의 모달리티 실패 시에도 나머지로 예측 가능

#### 가중치 설정 근거

| 모달리티 | 가중치 | 근거 |
|---------|--------|------|
| **이미지** | 0.4 | 얼굴 표정은 우울증의 가장 직관적/신뢰도 높은 지표 |
| **사운드** | 0.35 | 운율 변화(억양 저하, 말 속도 감소)는 우울증과 높은 상관관계 |
| **텍스트** | 0.25 | STT 오류 가능성, 내용은 간접적 지표 (표면적 의미만 분석) |

## 5. 고급 전처리: 얼굴 검출 및 캐시 시스템

### 선택 이유

| 기존 방식의 한계 | 해결 필요성 |
|-----------------|------------|
| **단순 Resize**는 배경 노이즈 포함 | 얼굴 영역만 정확히 크롭 필요 |
| **Haar Cascade 단독**은 정면 얼굴 외 검출률 저조 | 다양한 각도/조건에서 검출 필요 |
| **매번 검출 수행**은 학습 시 병목 | 캐시로 재사용 필요 |

#### 대안 비교 및 선택 근거

| 방법 | 장점 | 단점 | 선택 여부 |
|------|------|------|----------|
| **Haar Cascade 단독** | 빠름, 경량 | 정면 외 검출률 낮음 | X |
| **MTCNN** | 높은 검출률, 랜드마크 제공 | TensorFlow 의존성, 느림 | X |
| **dlib HOG** | 정확, CPU 최적화 | 측면 검출 약함 | X |
| **YUNet + Haar (2단계)** | DNN 정확도 + Fallback 안정성 | 약간 복잡 | **O (최종 선택)** |

**YUNet + Haar 2단계 방식 선택 이유**:
1. **YUNet DNN**: OpenCV 내장, 빠르고 정확한 얼굴 검출 (score ≥ 0.6)
2. **Haar Fallback**: YUNet 실패 시 Haar Cascade로 추가 시도
3. **회전 보정**: 랜드마크(눈 위치) 기반 기울기 자동 보정
4. **캐시 시스템**: 검출 결과를 JSON으로 저장 → 재학습 시 즉시 로드

### 구현 방법

- **구현 파일**: `hwa_in/clean_training.ipynb` (DepressionDataset 클래스)

- **핵심 로직**:
  ```python
  def _detect_face_bbox(self, rgb: np.ndarray):
      # 1차: YUNet DNN (정확도 우선)

          ok, faces = self._yunet.detect(rgb)
          if ok and faces is not None:
              # score ≥ 0.6, 얼굴 크기 ≥ 9% 필터링
              keep = [f for f in faces 
                      if f[4] >= 0.6 and f[2]*f[3] >= 0.09*area]
              if keep:
                  return best_face_with_landmarks
      
      # 2차: Haar Cascade (Fallback)
      for detector in (self._cascade_frontal, self._cascade_profile):
          faces = detector.detectMultiScale(gray, scaleFactor=1.1)
          if len(faces):
              return largest_face
      
      return None  # 검출 실패 → fail_policy에 따라 처리
  ```

- **참고 문서**:
  - [OpenCV YUNet Face Detection](https://docs.opencv.org/4.x/d0/dd4/tutorial_dnn_face.html)
  - [Haar Cascade Classifier](https://docs.opencv.org/4.x/db/d28/tutorial_cascade_classifier.html)

### 핵심 기능

1. **2단계 검출**: YUNet DNN(정확) → Haar Cascade(Fallback)
2. **회전 보정**: 눈 랜드마크 기반 얼굴 기울기 자동 보정
3. **캐시 시스템**: 검출 결과를 해시 기반 JSON 파일로 저장
4. **실패 정책**: `fail_policy="skip"`으로 검출 실패 샘플 자동 제외

## 요약 테이블

| 기술/기능 | 선택 이유 | 구현 방법 | 핵심 기능 |
|----------|----------|----------|----------|
| **이미지 모델 (ConvNeXt-Base)** | ViT 대비 소규모 데이터 안정성, ResNet 대비 높은 성능 | ImageNet 전이학습 + 3-Phase Training | 얼굴 표정 → 우울/비우울 이진 분류 |
| **사운드 모델 (Prosody 3채널)** | Wav2Vec2는 내용 중심, 프로소디는 운율 특화 | Mel+Pitch+RMS 3채널 → ConvNeXt | "어떻게 말했는가" 분석 |
| **텍스트 모델 (KoBERT + LogReg)** | BERT Fine-tuning 대비 과적합 방지, 임베딩만으로 충분 | 768-dim 임베딩 → Linear 분류 | 발화 내용 의미 분석 |
| **멀티모달 통합 (Late Fusion)** | Early Fusion 대비 디버깅 용이, 결측 처리 유연 | 독립 예측 → 가중 평균 | 3개 모달리티 결합 |
| **얼굴 검출 (YUNet + Haar)** | Haar 단독 대비 검출률 향상, MTCNN 대비 경량 | 2단계 검출 + 캐시 | 얼굴 크롭 + 회전 보정 |
